System Design

Distributed flash-sale order path
  • 1Nginx gateway balances API replicas.
  • 2Redis handles product cache and order queue.
  • 3Workers own the hot inventory write path.
  • 4Postgres stores products, orders, and final outcomes.
  • 5Prometheus scrapes API and worker metrics for Grafana.

Signals used during load tests

What Breaks

Saturation point and bottlenecks
  • AAPI/gateway EOFs appear under heavy connection pressure.
  • BSync writes push user latency directly onto Postgres row locks.
  • CAsync intake stays safer, but Redis queue depth grows during the 50-order Burst.
  • DMore replicas on one small host increase CPU and DB contention.

Improvements Made

Reliability and operability changes
  • IMoved order processing out of the request path.
  • IAdded idempotency keys for retry-safe clients.
  • IAdded atomic inventory decrement to prevent overselling.
  • IAdded Redis cache, rate limiting, and queue-depth backpressure.
  • IAdded k6 tests, Prometheus metrics, and Grafana panels.
